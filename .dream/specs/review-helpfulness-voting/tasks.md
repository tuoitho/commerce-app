# Implementation Plan

- [x] 1. Nền tảng persistence và compatibility

- [x] 1.1 Chuẩn hóa thực thể phản hồi và tạo nguồn dữ liệu vote
  - **Produces:** Migration up/down tạo `review_replies` và `review_helpfulness_votes`, backfill phản hồi hiện có, foreign key/unique/check/index theo design; sqlc models/queries được tái sinh; admin reply API, public review projection và user review history tiếp tục đọc/ghi đúng `adminReply`/`adminRepliedAt` từ nguồn mới.
  - **Scope:** Viết migration kế tiếp bằng TDD/integration-test-first; chuyển persistence của create/edit/delete phản hồi sang entity có UUID ổn định; sửa/xóa phản hồi khóa hàng reply bằng cùng `FOR UPDATE` protocol mà reply vote writer sẽ dùng; cập nhật toàn bộ review queries và repository mappings bị tác động; bảo toàn response shape của frontend-admin và frontend history; cập nhật fake repositories do interface thay đổi trong phạm vi task; không thêm helpfulness fields vào history/admin payload.
  - **Consumes:** Schema `product_reviews`, quan hệ users/reviews, admin reply routes và wire fields hiện có; data model, backfill rule và lifecycle reply đã duyệt trong `design.md`.
  - **Acceptance:** Phản hồi cũ giữ nguyên nội dung và thời điểm hiển thị sau up migration; sửa phản hồi giữ cùng UUID/vote và được serialize với reply vote writers; xóa phản hồi chờ các writer trước, sau đó xóa entity cùng mọi reply vote theo cascade; tạo lại sinh UUID mới và bắt đầu không có vote; chỉnh sửa review không xóa review vote; down migration chép phản hồi về schema cũ trước khi xóa bảng mới; admin list/update/delete và user history giữ hành vi/payload hiện có.
  - **Verification:** Focused migration/schema/repository integration tests cho backfill, constraints, up/down và lifecycle; focused admin review, user history và review edit regression tests; chạy `make db-up` khi PostgreSQL local khả dụng; chạy `make gen` và kiểm tra generated diff; chạy focused Go tests của các package bị tác động.
  - _Requirements: 4.3, 4.4, 4.5, 4.6, 6.4, 6.5, 6.6_

- [x] 2. Backend helpfulness contracts

- [x] 2.1 Mở rộng danh sách đánh giá công khai bằng tổng vote và viewer state
  - **Produces:** `GET /api/v1/products/{productId}/reviews` giữ envelope/pagination hiện có và bổ sung `helpfulness` bắt buộc cho review cùng `adminReplyId`/`adminReplyHelpfulness` khi có reply; optional-auth middleware cung cấp customer viewer ID từ JWT hợp lệ mà vẫn cho anonymous access.
  - **Scope:** Viết handler/use-case/repository tests trước; bổ sung domain/wire types đúng null/omitted semantics; aggregate vote theo tập review/reply ID của trang, không N+1 và không dùng denormalized counters; mở rộng guard bằng optional auth; giữ product validation, newest-first order, limit, summary sao và pagination hiện có.
  - **Consumes:** `review_replies` và `review_helpfulness_votes` từ task 1.1; JWT manager/context keys, Full Status Envelope, public review endpoint và pagination contract hiện có; approved `PublicReview` extension trong design.
  - **Acceptance:** Anonymous nhận hai count bắt đầu từ 0 và `viewerVote: null`; customer token hợp lệ nhận vote riêng của mình; admin token hợp lệ được xem nhưng không có viewer selection; token header sai/hết hạn nhận 401 để client refresh; reply fields cùng xuất hiện hoặc cùng bị lược bỏ; danh sách tối đa 10 review vẫn dùng số lượng truy vấn bị chặn theo trang thay vì theo số phần tử; rating summary, thứ tự và pagination không đổi.
  - **Verification:** Focused repository tests cho aggregate/viewer projection và query bound; use-case tests cho product/identity context; middleware/handler contract tests cho anonymous, customer, admin, invalid token, zero counts, reply absent/present, envelope và pagination; regression tests cho summary/order.
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 5.1, 5.2, 5.3, 5.5, 6.1, 6.2, 6.3_

- [x] 2.2 Cung cấp thao tác đặt vote idempotent cho review và reply
  - **Produces:** Hai endpoint customer-only `PUT /api/v1/reviews/{reviewId}/helpfulness` và `PUT /api/v1/review-replies/{replyId}/helpfulness`, nhận thuộc tính bắt buộc `vote: "helpful" | "unhelpful" | null` và trả trực tiếp `HelpfulnessState` trong Full Status Envelope.
  - **Scope:** Viết use-case/repository/HTTP tests trước; lấy user ID và role chỉ từ JWT context; validate body/UUID; trong transaction khóa hàng review/reply target bằng `FOR UPDATE` trước khi set, change, remove, same-state no-op và tính count; dùng database uniqueness làm invariant một user-một target; thêm domain errors và Vietnamese mappings đã duyệt; bao phủ stale reply UUID sau delete/recreate và concurrent writes.
  - **Consumes:** Persisted target identity và constraints từ task 1.1; `HelpfulnessVote`/`HelpfulnessState` và authentication context được ổn định bởi design/task 2.1; `AuthRequired`, `RequireRole(customer)` và response/error helpers hiện có.
  - **Acceptance:** Customer, kể cả tác giả review, có thể set/change/remove độc lập trên review và reply; gửi lại cùng desired state không đổi count; mỗi user có tối đa một hàng trên mỗi target; same-user concurrent writes kết thúc với một trạng thái hợp lệ và totals không âm; với hai customer cùng vote một target, writer được serialize sau quan sát vote đã commit trước trong response count; admin/anonymous bị 403/401; missing/invalid vote là validation error; review/reply không tồn tại trả đúng 404 tiếng Việt; UUID reply cũ không tác động reply tạo lại; response luôn phản ánh trạng thái đã lưu tại điểm mutation được serialize của đúng target.
  - **Verification:** Focused domain/use-case tests cho validation và self-vote; repository tests cho set/change/remove/idempotency/isolation/counts/cascade; same-user concurrency test; two-customer concurrency test chứng minh hai response có tổng lần lượt 1 và 2 theo thứ tự lock/commit và database cuối có tổng 2; handler/router tests cho method/path/body, 200/400/401/403/404/500, direct payload và Full Status Envelope.
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 3.2, 3.3, 3.4, 4.1, 4.2, 5.4, 5.5_
